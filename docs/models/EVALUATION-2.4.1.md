# Egoist Voice 2.4.1: качество и ресурсы

Пакет 2.4.1 проверен и установлен. Используется прежняя локальная GigaAM v3: plain RNNT INT8 для слов, E2E RNNT INT8 для пунктуации и регистра. Два этапа идут последовательно, по четыре CPU-потока. ASR использует CPU; GPU обслуживает интерфейс. Восемь моделей занимают 650 MB, проверенный payload — 841 MB.

## Реальный фоновый простой

После готовности установленного процесса: 20 снимков за 44.51 секунды. Все технические состояния — idle-or-completed. Измеритель не инициировал запись и не анализировал личное аудио. Машина: 16 логических CPU, 31.19 GiB физической памяти, видимой Windows; AMD Radeon Graphics и NVIDIA RTX 5070 Ti.

| Показатель | Измеренная 2.4.1 |
|---|---:|
| CPU, среднее всей машины | 0.0088% |
| CPU, максимальный интервал | 0.087% |
| Резидентная память процесса, working set | 917.5–917.6 MB |
| Private committed memory | 842.7–842.8 MB |
| GPU, максимум одного engine WDDM процесса | 0.00% |
| Dedicated GPU memory | 12.31 MB |
| Shared GPU memory | 3.89 MB |

Working set занимает около 2.74% RAM этой машины и включает общие страницы. Private memory — другой учёт выделенной памяти, включая выгруженные страницы. Эти числа нельзя складывать. GPU 0% означает нулевое показание в данных интервалах, а не обещание постоянного абсолютного нуля.

До обновления 2.4.0 наблюдалась в смешанных idle/recording состояниях: средний CPU 0.077%, working set 622–634 MB, private 999–1000 MB; GPU max engine 0.379%, dedicated 16.1 MB. Это другой возраст процесса и состояние нагрузки. Новая резидентная память выше, private ниже; причинный процент экономии по этим наблюдениям не установлен. Windows paging и файловый cache влияют на сравнение.

## Холодный процесс с распознаванием

Публичная человеческая запись ruls-test-0000 длится 11.35 секунды. По три свежих процесса точных payload 2.4.0 и 2.4.1 выполняли правильный Compact профиль с изолированными Data/Logs, без микрофона и скачиваний. Все шесть результатов побайтно совпали с прежним принятым текстом. Отдельный smoke фактически установленного EXE также совпал.

| Startup/load/decode/dispose/exit | 2.96–4.50 s | 2.25–2.86 s |
| Медиана полного процесса | 2.961 s | 2.371 s |

Это время включает загрузку обеих моделей и завершение WPF, поэтому его нельзя выдавать за обычную задержку после отпускания кнопки. В коротком CLI GPU отдельно не измерялся; provider CPU подтверждён исходником профиля. Контроль каждые 50 ms может пропустить более короткие пики. Разная внешняя нагрузка и cache не позволяют заявить универсальный прирост скорости по трём повторам. Исторические warm p50 135 ms/p95 268 ms на public80 относятся к отдельному старому замеру 2.4.0, а не к повторённому тесту новой версии.

## Изменения и проверка

Операции захвата, устройств и завершения отслеживаются вне UI dispatcher. Устаревшие callbacks исключаются; временная потеря микрофона и намеренная пауза разделены. Windows-default берётся заново при начале записи. Скрытые и свёрнутые окна отключают ненужные кадры, таймеры и повторяющиеся анимации. Настройки сохраняют громкость при быстром закрытии. Исправлен запуск с отключёнными анимациями Windows; start cue не подавляет первый аудиоблок.

Фактически прошли Full 1150, Compact 1143 + 7 ожидаемых Full-only пропусков, чистая Windows CI 1150. Exact final DLL: два варианта запуска, 24 состояния капсулы и 17 настроек; четыре процесса exit 0, фокус сохранён. UI тесты используют fake services и не доказывают все реальные драйверы или FPS. Updater: 12 вариантов транзакции, два public binding, Pester 24, Analyzer 0; искусственный отказ откатывается побайтно.

В установленной версии проверены все 545 файлов и реально загруженные managed/CAPI/ORT DLL. Базовый микрофон Windows выбран по поручению владельца; ручная пауза и 13 остальных свойств настроек сохранены. Пять прочих Data-файлов сохранили размер и время изменения; содержание истории и личного аудио не читалось. Установщик на рабочем компьютере не запускался, применена транзакционная замена payload. Чистая Windows installer lifecycle отдельно не проверена.

191 текстовый тест, 41 новый случай. Public80 saved-hypothesis replay остаётся побайтно прежним: 26 ошибок слов, 130 пунктуационных FP+FN, 241 raw character. Это не новый полный акустический прогон всех 80 записей на финальном EXE. Известные названия и слитные предлоги исправляются только с подтверждением второй аудиомодели и двумя неизменными anchors. Неизвестные слова, обычный союз «и» и окончания не угадываются.

Акустический прирост 5–10% не доказан. Фиксированная донастройка на контроле192 ухудшила ошибки слов 114→122 и отклонена. Raw E2E на dev128 дала 94 ошибки против 68 основной модели; общий перенос её слов тоже отклонён. Скриншоты «Инпила» и «энергетик» не содержат аудио, поэтому исправление именно личного произношения/окончания не подтверждено.

## Оценка и дальнейшая оптимизация

В измеренном простое нагрузка небольшая: CPU около 0.01%, GPU простаивает, resident RAM около 0.92 GB. Для этой машины это разумный вариант. Сильной фоновой нагрузки не обнаружено. Модели оставлены готовыми: их выгрузка уменьшила бы удерживаемую память, но добавила бы загрузку перед следующей диктовкой. На первом распознавании память может приблизиться к 1.1 GB. Длительный сеанс и все реальные устройства не проверены; finite tests не дают гарантии безошибочной работы.

Matched синтетические WPF случаи по пять секунд подтвердили снижение hidden allocations и CPU части скрытых состояний; CPU idle/hidden-processing не улучшился во всех случаях. Универсальная экономия или гарантированный прирост точности не заявляются.
