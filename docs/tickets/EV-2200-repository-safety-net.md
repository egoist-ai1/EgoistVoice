# EV-2200 — предохранительная сетка репозитория

- Status: `APPROVED — выполняется первым, до любого другого тикета`
- Specification: [Амендмент 002](../specs/002-voice-2.2-brand-ui-and-independence.md)
- Depends on: ничего
- Artifact boundary: только локальный Git. Без remote, без push, без тегов,
  без публикации, без изменения кода продукта.

## Зачем

В рабочем каталоге лежит около 68 изменённых файлов — кандидат 2.1.1 и вся
работа по 2.2 — поверх коммита `f1f5997` в `main`. Это состояние существует
только на диске примерно с 27 июля. Один неосторожный `git checkout`, `git
clean` или сбой инструмента уничтожает неделю работы безвозвратно.

`AGENTS.md` требует сохранять «грязный» кандидат и не публиковать его. Коммит
в отдельную ветку выполняет оба требования одновременно: работа становится
восстановимой, а `main` и релизная линия 2.1.0 остаются нетронутыми.
Зафиксировать — не значит выпустить.

## Наблюдаемый результат

Все текущие изменения зафиксированы в ветке `v2.2-wip`. `git status` чист.
`main` указывает на прежний коммит. Любая последующая правка обратима.

## Область и вероятные файлы

- Новая ветка `v2.2-wip` от текущего `HEAD`.
- Один коммит со всем текущим рабочим набором.
- При необходимости — дополнение `.gitignore`: `bin/`, `obj/`, приватный
  корпус, WAV, скачанные модели, `artifacts/**` с крупными бинарниками.
- Ни один файл продукта не меняется по содержанию.

## Порядок

1. `git status --porcelain` — записать полный список до изменений.
2. Проверить `.gitignore` до `git add`: приватные аудиозаписи и модели не
   должны попасть в историю **ни при каких условиях**.
3. `git switch -c v2.2-wip`, `git add -A`, один коммит с честным описанием:
   кандидат 2.1.1 плюс работа по 2.2, EV-2205 не завершён, релиз не заявлен.
4. Убедиться, что `main` не сдвинулся: `git log --oneline main -1` по-прежнему
   `f1f5997`.
5. Записать хэш нового коммита в `STATUS.md`.

## Блокеры и зависимости

- Если в индекс попадает WAV, модель или что-то тяжелее нескольких мегабайт —
  остановиться и сначала исправить `.gitignore`.
- Если `.git/index.lock` заблокирован другим процессом — не удалять его
  вслепую; сначала выяснить, какой процесс держит.

## Проверка

1. `git status --porcelain` пуст.
2. `git branch --show-current` — `v2.2-wip`.
3. `git log --oneline main -1` — `f1f5997`, тег 2.1.0 не тронут.
4. `git ls-files '*.wav' '*.gguf' '*.bin'` — пусто.
5. `git count-objects -vH` — прирост истории объясним.
6. Пробный `git stash` / `git stash pop` подтверждает работоспособность
   отката.
