# Egoist Voice 2.0 — техническая спецификация

Опирается на `00-audit.md` (что сломано) и `01-market.md` (что делают лучшие). Все числа здесь —
целевые значения, пригодные для приёмки. Где число взято из измерения конкурента или
исследования, это указано.

**Принцип, определяющий все решения ниже:** Egoist Voice уже занимает пустую нишу — полностью
локальная диктовка с лучшим доступным русским ASR и latency ниже облачных лидеров. v2.0 не
меняет позиционирование. Она убирает три слоя отставания: надёжность, полировку взаимодействия,
продуктовые мелочи.

---

## Часть I. Надёжность и потоковая модель

Это фундамент: без него полировать анимацию бессмысленно, потому что она замирает на время
распознавания.

### 1.1 Модель потоков

```
┌─ UI-поток (STA, Dispatcher) ──────────────────────────────────┐
│  WPF-визуал, Storyboard, CompositionTarget.Rendering          │
│  Clipboard (требует STA — это не случайность, а контракт)      │
│  ТОЛЬКО обновление состояния. Никакого ASR, никакого I/O.     │
└───────────────────────────────────────────────────────────────┘
┌─ Поток ввода (выделенный STA + свой message loop) ────────────┐
│  SetWindowsHookEx(WH_MOUSE_LL)  ← ставится ЗДЕСЬ, не на UI     │
│  SetWindowsHookEx(WH_KEYBOARD_LL)                              │
│  Колбэк делает ТОЛЬКО: разбор структуры, сверку с биндингом,   │
│  чтение кэша «активное окно — игра?», PostMessage наружу.      │
│  Бюджет колбэка: ≤ 1 мс. Жёсткий предел системы — 300 мс.      │
└───────────────────────────────────────────────────────────────┘
┌─ Аудиопоток (WASAPI capture callback) ────────────────────────┐
│  Копирование в кольцевой буфер, расчёт RMS/peak/FFT.           │
│  Никакого файлового I/O. Запись на диск — отдельный writer.    │
└───────────────────────────────────────────────────────────────┘
┌─ Пул задач (ThreadPool, ConfigureAwait(false) везде) ─────────┐
│  ASR-декод, чтение и запись файлов, ModelManager, логи.        │
│  Возврат на UI — только явным Dispatcher.InvokeAsync.          │
└───────────────────────────────────────────────────────────────┘
```

**Правило, которое нужно записать в `AGENTS.md` проекта:** в `Services/` и `Core/` каждый `await`
получает `.ConfigureAwait(false)`. Исключение ровно одно и оно должно быть закомментировано —
`ClipboardService`, который обязан выполняться на STA-потоке. Сейчас он работает на STA
**случайно**, потому что продолжения возвращаются в Dispatcher; после введения
`ConfigureAwait(false)` это сломается с `ThreadStateException`, если не сделать маршалинг явным.

### 1.2 Хук ввода

| Требование | Значение |
|---|---|
| Поток | выделенный, `ApartmentState.STA`, `IsBackground = true`, свой `GetMessage`-цикл |
| Работа в колбэке | ≤ 1 мс: `Marshal.PtrToStructure`, сверка кода кнопки, чтение `volatile bool _foregroundIsGame`, `PostMessage` |
| Подавление события | никогда — `CallNextHookEx` безусловно (**сохранить текущее поведение**) |
| Определение «игра» | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` обновляет кэш **вне** хука. `Process.MainModule` вызывается в пуле задач, результат кэшируется по `processId` |
| Watchdog | если за `N` секунд активности мыши не пришло ни одного события — считать хук снятым по `LowLevelHooksTimeout`, переустановить, записать в лог |
| Отпускание клавиатурного хоткея | `WH_KEYBOARD_LL` вместо `DispatcherTimer` 16 мс. Целевая латентность **≤ 2 мс** против текущих 0–16 мс |

`LowLevelHooksTimeout` по умолчанию 300 мс; при превышении Windows снимает хук молча. Watchdog —
не перестраховка, а обязательный элемент.

### 1.3 Захват аудио

| Параметр | 1.6.5 | 2.0 |
|---|---|---|
| API | NAudio `WaveInEvent` (**MME/winmm**) | `WasapiCapture` (shared) |
| Латентность API | 30–100 мс | 10–30 мс |
| Открытие устройства | **при нажатии, внутри хука** | при старте приложения, микрофон открыт постоянно |
| Pre-roll | нет — первый слог теряется | **кольцевой буфер 500 мс**, при нажатии берётся задним числом |
| Запись на диск | в аудио-колбэке под общим локом | отдельный writer-поток; при задержке диска аудио не теряется |
| Смена устройства | не отслеживается | `IMMNotificationClient` → переоткрытие без прерывания сессии |
| Выбор устройства | нет | список в настройках + «по умолчанию» |
| Передача в ASR | **третье чтение WAV с диска** | `float[]` из памяти напрямую |

Pre-roll — это функция, которую просит весь рынок и которую **никто не внедрил**: у Wispr Flow
«Missing first words» — официальная статья в Known Issues, у Handy — «первые несколько слов
обычно теряются». Решение известно и стоит один кольцевой буфер.

Размер 500 мс выбран как компромисс: покрывает и открытие устройства (20–150 мс), и типичное
опережение речи относительно нажатия (человек начинает говорить до того, как палец дошёл до
кнопки).

**Чего НЕ делать:** обрезку ведущей и хвостовой тишины перед подачей в ASR. Измерено: VAD-cut
даёт **+7,9 п.п. WER**, AGC — **+6,1 п.п.**, вместе — **+8,8 п.п.** Декодер теряет границу
предложения и склеивает фразы. Из шумоподавления допустимы только HPF 80 Гц и pre-emphasis
(−1,3 п.п.), и только за настройкой, выключенной по умолчанию.

### 1.4 Управление жизненным циклом

| Дефект | Исправление |
|---|---|
| `Dispose` рецогнайзера под активным декодом | `Dispose` берёт `_decodeLock`; при закрытии — отмена операции, ожидание, затем освобождение |
| `Wait(2 s)` на UI-потоке при выходе | асинхронное завершение, окно закрывается сразу |
| Гонка `_whisperWarmUp ??=` | `Interlocked.CompareExchange` или `Lazy<Task>` |
| `_operationCancellation?.Dispose()` под возможным использованием | владение токеном привязано к операции, не к полю |
| Утечка временного WAV при отмене | `audioPath` известен **до** `StopAsync`; удаление в `finally` безусловно |
| Ошибка «Запись уже запущена» как «Нет микрофона» | подключить существующий `GetMicrophoneError` (сейчас мёртвый код) |

### 2.2 Ключевое решение: Whisper по условию, а не всегда

Сейчас `Task.WhenAll(gigaTask, whisperTask)` запускает оба движка на каждой диктовке. Whisper
даёт ~0,28 с из ~0,4 с p95 и **почти всегда отбрасывается**.

Новая логика:

```
1. GigaAM декодирует всегда.
2. Whisper запускается ТОЛЬКО если выполнено хотя бы одно:
   а) в выводе GigaAM есть латиница (≥1 символ) — признак попытки распознать англ.;
   б) в выводе GigaAM есть фонетическая русификация из «карты подозрений»
      (жёсткий список вида «джемини», «висперлардж», «докер», «гитхаб»…);
   в) пользователь явно включил режим смешанной речи (в трее / per-app профиле);
   г) активное приложение помечено как «код/терминал» в per-app профиле.
3. Пока Whisper считает, состояние капсулы — «Уточняю термины»,
   а не безымянное «Распознаю». Пользователь понимает, за что платит задержкой.
```

Ожидаемый эффект: **−150…−300 мс p95 на GPU-ПК, −1…−4 с на CPU-only, −50 % CPU за диктовку** для
подавляющего большинства (чисто русских) сессий. При этом качество на смешанной речи не падает,
потому что триггер (а) срабатывает ровно тогда, когда GigaAM уже показал латиницу.

Риск: GigaAM может фонетически русифицировать английский термин целиком, не оставив латиницы
(«Gemini» → «Джемини»). Именно для этого нужен пункт (б) — «карта подозрений». Она пополняется из
пользовательского словаря автоматически: каждый английский термин в словаре порождает свои
вероятные русские транскрипции.

### 2.3 Прочие изменения в ядре

| Изменение | Ожидаемый эффект |
|---|---|
| **Прогрев GigaAM** тихим аудио при старте (сейчас только создаётся рецогнайзер) | первые 2 вызова ONNX Runtime в 3–5 раз медленнее — это снимается |
| **Параллельный декод чанков** (пул `OfflineStream`) вместо строгого `for` | для записей >22 с ускорение ≈ ×min(N чанков, ядра/2) |
| **Аудио в память, а не третье чтение WAV** | −5…−40 мс |
| **`AreAllModelsReady` и `AppLog` из горячего пути** — кэш в памяти, асинхронный лог | −5…−25 мс, устойчивее при активном антивирусе |
| **`WhisperProcessor` переиспользуется**, а не создаётся заново | −десятки мс, когда Whisper всё же нужен |
| **Ленивая загрузка Whisper**: не держать 574 МБ в RAM, пока не понадобился; выгрузка через 10 мин бездействия | **−600…−900 МБ RSS** у tray-утилиты |
| Оценить `Provider = "cuda"` для GigaAM (сейчас жёстко `"cpu"`) | замерить; RNN-T плохо ускоряется GPU (RTFx 50 → 130), выигрыш не гарантирован |

**Что НЕ менять:** модель. GigaAM v3 e2e-RNNT INT8 остаётся. Альтернативы проверены:
GigaAM Multilingual слаба на английском (EN CV 21,5 %); потоковой GigaAM не существует;
plain RNN-T даёт −2,9 п.п. WER, но требует отдельных моделей пунктуации и ITN в установщике.

### 2.4 Сегментация: три исправления

```csharp
// 1. Overlap ВСЕГДА, а не только в fallback-ветке.
//    Сейчас: при найденной тишине start = end (перекрытие ноль).
start = Math.Max(0, end - OverlapSamples);

// 2. Выбирать САМУЮ ДЛИННУЮ паузу, а не самую правую.
//    Сейчас: candidate.Boundary > current.Boundary.
if (candidate.SilenceLength > current.SilenceLength) current = candidate;

// 3. Порог тишины — адаптивный: перцентиль энергии записи,
//    а не абсолютный SilenceRms = 0.009 (~-40,9 dBFS).
var noiseFloor = Percentile(windowEnergies, 0.15);
var silenceThreshold = Math.Max(AbsoluteFloor, noiseFloor * 1.8);
```

**Дедупликация стыков** сейчас не работает: `FindExactOverlap` сравнивает токены как есть, а
GigaAM v3 e2e выдаёт пунктуацию, поэтому `"три,"` ≠ `"три"`. Исправление — нормализовать
пунктуацию и регистр **перед** сравнением, сравнивать нормализованные формы, склеивать исходные.
Дополнительно ограничить окно поиска хвостом последнего чанка, а не всем накопленным текстом
(сейчас при повторе фразы возможно ложное удаление до 12 слов).

### 2.5 Селектор: защита от галлюцинаций

Текущая формула позволяет `credibleEnglish` обойти проверку длины: галлюцинация Whisper в 5 раз
длиннее вывода GigaAM, но с латиницей ≥45 %, выигрывает безусловно.

```
Изменения:
1. Проверка длины применяется ВСЕГДА, включая ветку credibleEnglish.
2. Верхняя граница ужесточается с 1.8× до 1.5×.
3. Добавляется проверка на повтор: если Whisper содержит один и тот же
   n-gram (n≥3) более 2 раз подряд — это галлюцинация, вывод отбрасывается.
4. Whisper перестаёт быть жёстко WithLanguage("ru"): когда он запускается
   по триггеру смешанной речи, язык не форсируется.
```

**Гибридное слияние** (взять русский от GigaAM, английские термины от Whisper) в v2.0 **не
делаем**. Это выравнивание двух транскриптов по времени — отдельная задача с высоким риском
регрессии. Правильный путь к тому же результату дешевле: пользовательский словарь.

### 2.6 Постобработка

Единый детерминированный конвейер, применяемый к результату **любого** движка. Сейчас у Whisper
и GigaAM два разных алгоритма абзацевания — это устраняется.

**(1) Пользовательский словарь.** Файл `%LOCALAPPDATA%\EgoistVoice\dictionary.json`, редактируемый
из трея. Три вида записей:

```jsonc
{
  "terms": [
    // Простая подмена с учётом морфологии через словоформы
    { "spoken": ["питон", "пайтон"], "written": "Python" },
    { "spoken": ["гитхаб"], "written": "GitHub" },
    // Фраза → фраза (сниппет)
    { "spoken": ["моя подпись"], "written": "С уважением,\nРодион" },
    // Регулярное правило (для продвинутых)
    { "pattern": "(?i)\\bкубер(нетес)?\\b", "written": "Kubernetes" }
  ]
}
```

**Важно:** нельзя повторить ошибку Windows Voice Access, где словарь улучшает только список
предложений при коррекции, но не первичное распознавание. Наш словарь работает на двух уровнях:

- как `initial_prompt` для Whisper (уже реализовано для зашитых терминов);
- как детерминированная подмена на постобработке — **это основной механизм**.

Contextual biasing sherpa-onnx использовать **нельзя**: hotwords требуют transducer-модели с
`modified_beam_search`, а GigaAM в sherpa-onnx присутствует как NeMo CTC. Ограничение
архитектурное, а не настроечное. Измеренная альтернатива даёт те же 1–2 п.п. при задержке
0,02 мс вместо 80 мс.

**(2) Голосовые команды.** Распознаются только в позициях, где они не могут быть частью речи
(окружены паузами по таймингам чанков либо в начале/конце фразы):

| Сказано | Результат |
|---|---|
| «новая строка», «с новой строки» | `\n` |
| «новый абзац» | `\n\n` |
| «запятая», «точка», «двоеточие», «тире», «вопросительный знак» | соответствующий знак |
| «открыть скобку» / «закрыть скобку», «кавычки» | `(` `)` `«` `»` |
| «с большой буквы» | капитализация следующего слова |
| «удалить последнее слово» | удаление |
| «отправить» / «энтер» (опционально, за настройкой) | вставка + Enter |

Список закрытый и настраиваемый. Ключевое требование — **не срабатывать в обычной речи**. Слово
«точка» в «точка входа» командой быть не должно; поэтому команда требует либо паузы ≥300 мс с
обеих сторон, либо позиции в конце высказывания.

**(3) Нормализация чисел, дат, единиц.** WFST-подход (эталон — NeMo `nemo_text_processing`,
русский поддержан), но в v2.0 реализуем **компактный детерминированный нормализатор на C#**, а не
тянем питоновую зависимость:

| Вход | Выход |
|---|---|
| «двадцать пять» | 25 |
| «сто двадцать три тысячи» | 123 000 |
| «пятое июля две тысячи двадцать шестого» | 05.07.2026 |
| «три с половиной процента» | 3,5 % |
| «пятнадцать минут» | 15 минут |
| «плюс семь девятьсот…» | +7 900 … |

Измеренный вклад отдельно: **−0,7 п.п. WER**. Обязательно за тумблером — в диктовке
художественного текста «двадцать пять» должно оставаться словами.

**Что НЕ делать: LLM-постобработку.** Прямой воспроизводимый опыт: на сильной ASR-модели
нейронная коррекция даёт **отрицательный** эффект — «исправляет» уже правильный текст.
Детерминированная замена даёт тот же 1–2 п.п. при 0,02 мс вместо 80 мс.

### 2.7 Корпус и метрики — предусловие любых правок порогов

Без этого пункта весь раздел 2 — подгонка под единичные фикстуры, что уже признано в
`docs/research.md:39`.

```
tests/corpus/
  ru-clean/        20 фраз, тихая комната, обычный темп
  ru-fast/         15 фраз, быстрая речь
  ru-noisy/        15 фраз, фон: клавиатура, вентилятор, музыка
  ru-en-mixed/     25 фраз с англ. терминами — ГЛАВНЫЙ набор для нас
  ru-numbers/      15 фраз с числами, датами, единицами
  ru-longform/     5 записей 60–180 с
  ru-commands/     10 фраз с голосовыми командами
  reference.jsonl  эталоны, вычитанные вручную
```

Из полевого исследования: **разница между моделями держится в пределах ±1 п.п., разница между
корпусами — 15–20 п.п., разница между сырыми и вычитанными эталонами — 7 п.п.** Один битый эталон
сдвигает итоговый WER на 5 п.п. и может скрыть 19-п.п. разрыв между моделями. День на чистку
эталонов окупается быстрее недели подбора архитектуры.

Гейт в CI: `dotnet test` считает WER/CER по корпусу и p50/p95 latency; регрессия WER >0,5 п.п.
или p95 >15 % — красный билд.

### 3.4 Waveform: переписать

| Параметр | 1.6.5 | 2.0 |
|---|---|---|
| Реализация | 24 `Border` в `ItemsControl` | **один `DrawingVisual`**, `DrawRoundedRectangle` в цикле |
| Аллокации на кадр | 48 боксов `double` (24 `ScaleY` + 24 `Opacity`) | 0 |
| Источник данных | один RMS-скаляр | **4–6 частотных полос** (лёгкое FFT 256 точек на аудиопотоке) |
| Полосы | 24 × (2 × 22), радиус 1 | 20 × (3 × 24), **радиус = ширина/2** (капсулы) |
| Отображение амплитуды | линейное | **гамма-коррекция `pow(v, 0.7)`** — референс Handy |
| Цветовой разброс центр↔край | `#FE2E3A` ↔ `#E11E2E` (неразличим) | яркость 100 % ↔ 55 %, плюс сдвиг насыщенности |
| Частота обновления | жёсткий порог 12 мс → 60 fps на 120 Гц, 72 на 144 Гц | **delta-time без троттлинга**, нативно 60/120/144/165/240 |
| `Opacity` | присваивается всем 24 полосам одинаково | одно значение на контейнере |
| `barAlpha` | считается внутри цикла × 24 | один раз на кадр |
| Эмит уровня при скрытом оверлее | эмитится всегда | **не эмитится** (урок Handy: рост памяти рендерера) |

Сглаживание, которое **сохраняется** — оно сделано правильно: асимметричный attack/release
(`0.62` / `0.20`) плюс второй экспоненциальный фильтр τ=35 мс на полосу.

Гамма-коррекция 0,7 — не эстетика. Линейная амплитуда выглядит вяло на тихой речи; экспонента
делает столбики живыми при том же сигнале.

### 3.5 Тень и подложка

Сейчас «тень» — это три концентрических хайрлайна `#0C000000` / `#16000000` / `#26000000`
**без размытия**. На светлом фоне читается как три вложенных кольца, а не мягкая тень.

Два пути, оба реализуются, выбор — за замером:

**A. Кэшированный `DropShadowEffect`.** `BlurRadius=18, ShadowDepth=4, Direction=270,
Opacity=0.45` на слое с `CacheMode="BitmapCache"`. Просто, работает везде, стоит одного
кэшированного слоя.

**B. DWM.** `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE, DWMSBT_TRANSIENTWINDOW)` +
`DWMWA_WINDOW_CORNER_PREFERENCE` на Win11 22H2+, с graceful-фолбэком на A. Требует отказа от
`AllowsTransparency=True` в пользу `WindowChrome` — это заметная переработка, но она **заодно
чинит** `TextRenderingMode="ClearType"`, который сейчас no-op на layered-окне.

Начинаем с A (Фаза 2), B оцениваем прототипом (Фаза 4).

**`PixelPerfectCapsuleBorder` сохраняется**, но с кэшированием: `RenderTargetBitmap`
перерисовывается только при изменении размера, DPI или кистей — не на каждый `OnRender`. Сейчас
на анимацию ширины это ~26 кадров × 4 RTB ≈ 40+ МБ за 180 мс, часть в LOH.
`RenderOptions.SetBitmapScalingMode` переезжает в конструктор.

### 3.6 Анимации: кривые и тайминги

Fluent-принцип: **вход замедляется** (decelerate, объект «прилетает и мягко останавливается»),
**выход ускоряется** (accelerate, объект «уносится»). Сейчас у выхода easing вообще нет.

| Событие | Свойства | Длит. | Кривая |
|---|---|---|---|
| **Появление** | scale 0.92→1 (origin — прижатый край), opacity 0→1, translateY 8→0 | **220 мс** | `KeySpline 0.1, 0.9, 0.2, 1.0` (decelerate) |
| **Исчезновение** | scale 1→0.94, opacity 1→0, translateY 0→6 | **140 мс** | `KeySpline 0.7, 0.0, 1.0, 0.5` (accelerate) |
| **Морфинг ширины** | `RootBorder.Width` | 200 мс | `KeySpline 0.2, 0.0, 0.0, 1.0` |

**`SetProcessingState` перестаёт рестартовать `SpinStoryboard`** при обновлении прогресса

Reduced Motion — текущая реализация (`!SystemParameters.ClientAreaAnimation ||

### 4.2 Позиционирование и Z-порядок

```
1. Clamp по work area ТЕКУЩЕГО монитора (MonitorFromPoint + GetMonitorInfo),
   а не по VirtualScreen. Сейчас капсула может лечь под панель задач
   или в «дыру» между мониторами разной высоты и стать невидимой.

2. Подписка на SystemEvents.DisplaySettingsChanged.
   Сейчас при отключении монитора капсула остаётся за экраном до следующего показа.

3. Появление на мониторе, где курсор мыши (референс Handy).

4. Принудительный SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE|SWP_NOMOVE|SWP_NOSIZE)
   при каждом показе и по таймеру во время записи.
   Handy отдельно отмечает, что штатный always-on-top перебивается.

5. Позиция переустанавливается ЕЩЁ РАЗ после Show() —
   WM_DPICHANGED затирает первую установку на мульти-DPI.

6. Перетаскивание к краям с прилипанием и запоминанием позиции per-monitor.
   Wispr Flow чинил это 9 июля 2026: панель «could land right on top of
   something you needed next, like the send button in Gmail».
```

Опционально: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` за настройкой — сейчас капсула
попадает в скриншоты и записи экрана.

### 4.3 Вставка текста

**Матрица методов** (референс Handy — шесть вариантов), с автоопределением:

| Метод | Когда |
|---|---|
| `Ctrl+V` | по умолчанию |
| **`Ctrl+Shift+V`** | **автоматически** для терминалов: Windows Terminal, cmd, PowerShell, mintty, PuTTY, Alacritty, WezTerm, kitty, Hyper, MobaXterm, ConEmu — референс OpenWhispr, лучшее решение на рынке |
| `Shift+Insert` | ручной выбор |
| Прямой ввод (`KEYEVENTF_UNICODE`) | ручной выбор; медленно и ломается об автодополнение |
| Только буфер | ручной выбор |

**Сохранение и восстановление буфера обмена** — референс VoiceInk, лучшая реализация на рынке:

```
1. Снимок ВСЕХ форматов данных буфера, не только строки.
2. Запись нашего текста + служебного формата с UUID сессии.
3. Пауза 60 мс (настраивается 60–200) → SendInput.
4. Пауза 50 мс → проверка: лежит ли в буфере ВСЁ ЕЩЁ наш текст
   И наш UUID? Если пользователь успел скопировать своё —
   восстановление НЕ выполняется.
5. Восстановление снимка.
```

Слишком рано нажать Ctrl+V → вставится предыдущее содержимое. Слишком рано восстановить →
затрётся то, что не успело вставиться. Это источник половины багов вставки на рынке.

**Прочее:**

- `Task.Delay(80)` заменяется опросом `GetForegroundWindow` с шагом 10 мс и предельным
  таймаутом — экономия до 70 мс в типичном случае.
- Санация состояния модификаторов перед `SendInput`: если пользователь держит Shift, уйдёт
  Ctrl+Shift+V вместо Ctrl+V.
- `ExtraInfo` помечается сигнатурой приложения, чтобы наш инжект можно было отфильтровать.
- `KEYEVENTF_SCANCODE` со скан-кодами — сейчас `ScanCode = '\0'`, и приложения, читающие
  скан-коды (DirectInput-игры, RDP, часть VM), нажатия не видят.
- **Fallback-окно, если фокуса нет ни в одном текстовом поле** — эту задачу на всём рынке решает
  ровно один OSS-проект. Все остальные молча теряют текст либо вставляют не туда.
- **Не вставлять в менеджеры паролей**: жёсткий список (1Password, Bitwarden, KeePass, Windows
  Hello) — диктовка приостанавливается с явным уведомлением.

`VK_V` (0x56) вместо символа мы уже шлём — здесь текущая реализация правильна и это надо
сохранить. Wispr Flow держит противоположное в Known Issues: «inserts incorrectly on non-QWERTY
keyboard layouts».

**UIPI остаётся нерешаемым** без `uiAccess="true"` (требует подписи и установки в
`Program Files`). Минимум — **честная диагностика**: определять, что целевое окно elevated, и
показывать «Окно запущено от администратора — нажмите Ctrl+V» вместо молчаливой потери текста.
`SendInput` при блокировке UIPI не сообщает об ошибке ни возвращаемым значением, ни
`GetLastError`.

| **Esc отменяет** | ❌ (окно не фокусируемо) | **добавить через `WH_KEYBOARD_LL`**, перебиндиваемо (конфликт с Vim) |
| Гибрид «короткий тап = toggle, удержание = PTT» | ❌ | добавить (референс Superwhisper Mouse Shortcut) |
| Отпускание клавиатурного хоткея | опрос 16 мс | `WH_KEYBOARD_LL`, ≤2 мс |
| Поведение в играх | **полное отключение** по списку из 19 процессов | настраиваемо: отключить / разрешить / только клавиатура; список редактируется; индикация в трее |

### 4.6 Доступность

Сейчас — ноль: ни одного `AutomationProperties.*` во всём проекте, окно `Focusable="False"` +
`WS_EX_NOACTIVATE` делает клавиатурную навигацию невозможной в принципе.

Минимум для v2.0:

- `AutomationProperties.Name` на каждом состоянии и кнопке;
- `AutomationProperties.LiveSetting="Polite"` на центральной зоне — смена состояния объявляется
  скринридером;
- объявление начала и конца записи, результата вставки, текста ошибки;
- Esc как отмена (см. 4.5) — работает без фокуса окна, через хук;
- `HighContrast` — уже реализовано честно, **сохранить**.

Полноценная клавиатурная навигация по капсуле противоречит `WS_EX_NOACTIVATE` (окно не должно
красть фокус) и в v2.0 **не делается**. Отмена доступна через Esc и через трей.

### 4.7 Мелкая эргономика

- `Cursor="SizeAll"` и `ToolTip="Перетащить"` убираются со всей площади — остаётся грип-зона слева
  либо перетаскивание только по пустой области. Сейчас подсказка всплывает поверх капсулы во время
  диктовки.
- `CustomShortcutDialog` открывается у курсора или трея, а не `CenterScreen` (сейчас всегда
  основной монитор, даже если трей на втором); получает скругление и тень.
- **История диктовок** с retry — «одна из самых частых просьб поддержки» по словам Wispr Flow.
  Хранится локально, лимит по количеству, очистка одной кнопкой.
- **Постепенная деградация присутствия** (референс Wispr Flow Android): после N секунд в `Ready`
  капсула сжимается в точку 12 × 12 у края экрана; при активации разворачивается обратно.
  Опционально.

## Часть VI. Что сознательно не делаем

| Отклонено | Почему |
|---|---|
| **LLM-постобработка транскрипта** | измерено: на сильной ASR эффект отрицательный, модель «исправляет» правильное. Детерминированная замена даёт тот же 1–2 п.п. при 0,02 мс вместо 80 мс |
| **Обрезка тишины перед ASR** | измерено: VAD-cut +7,9 п.п. WER, AGC +6,1, вместе +8,8 |
| **AGC / агрессивный денойз** | там же |
| **Streaming по умолчанию** | измерено: нарезка стоит ≈6 п.п. WER. Только опциональный режим с предупреждением |
| **Смена ASR-модели** | GigaAM Multilingual слаба на английском (EN CV 21,5 %); потоковой GigaAM не существует; plain RNN-T требует отдельных моделей пунктуации и ITN |
| **Hotwords sherpa-onnx** | архитектурно недоступны: требуют transducer + `modified_beam_search`, а GigaAM присутствует как NeMo CTC |
| **Гибридное слияние транскриптов** | выравнивание двух выводов по времени — высокий риск регрессии; словарь даёт тот же результат дешевле |
| **Полный редизайн под WinUI 3 / Fluent** | размывает айдентику; текущий чёрно-красный язык — актив |
| **Облачный режим** | ломает единственный незанятый на рынке дифференциатор |
| **Полная клавиатурная навигация по капсуле** | противоречит `WS_EX_NOACTIVATE`; отмена решается через Esc-хук |
| **`uiAccess="true"`** | требует подписи и установки в `Program Files`; вместо этого — честная диагностика elevated-окна |
