## 1. Карта рынка

| Сегмент | Кто | Экономика |
|---|---|---|
| **AI-native** | Wispr Flow, Aqua Voice, Willow Voice, Superwhisper | Подписка $8–15/мес, облако + LLM-постобработка |
| **Local-first, разовая покупка** | VoiceInk ($25–49), MacWhisper (€59), Whisper Notes ($6.99) | whisper.cpp / Parakeet локально |
| **OSS** | Handy (27,2k★), Buzz (19,7k★), Whispering, OpenWhispr | Бесплатно |
| **Легаси и ОС** | Dragon v16 ($699), Win+H, Voice Access, macOS Dictation, Talon | Лицензия / встроено |
| **Российские клоны** | Поток, Диктуй, SpeakFlow, VoiceBoard, Vox | 290–690 ₽/мес, облако |

**Главный факт для нас:** пересечение «полностью офлайн» × «хороший русский» **пусто**.
GigaAM v3 под MIT даёт средний WER 8,3 % против 21,0 % у Whisper large-v3 на русских доменах,
работает на CPU — и **ни один российский продукт диктовки её не использует**. Использует
Handy — иностранный OSS.

Egoist Voice уже стоит в этом пустом пересечении. Это не «догоняющая» позиция.

## 2. Что стало стандартом де-факто в 2026

Обязательное:

1. **Push-to-talk удержанием одной клавиши как дефолт.** Fn на macOS, Ctrl+Win или Alt на
   Windows. Ключевое: **встроенные средства ОС этого не дают вообще** — ни Win+H, ни Voice
   Access, ни macOS Dictation не имеют настоящего PTT, только toggle. Это структурный водораздел
   между «системной» и «продуктовой» диктовкой.
2. **Двойной тап того же хоткея = hands-free.** Wispr Flow, Willow. Один жест — два режима.
3. **Плавающий pill/bar, прижатый к краю экрана**, а не диалог по центру.
4. **Waveform как индикатор записи.** Есть у Handy, Superwhisper, Wispr Flow, Vibe. Нет у Win+H,
   Voice Access, macOS Dictation, Dragon, Talon.
5. **Явно различимые состояния «записываю» и «распознаю».**
6. **Esc отменяет**, причём перебиндиваемо (конфликт с Vim и терминалами).
7. **Автоматическое сохранение и восстановление буфера обмена** — гигиенический минимум.
8. **Персональный словарь + сниппеты.** Есть у всех платных без исключения.
9. **Автопереключение конфигурации по активному приложению.** VoiceInk Power Modes, Superwhisper
   auto-activation rules, Wispr Flow Styles.
10. **История диктовок с retry.** Wispr Flow называет retry «одной из самых частых просьб
    поддержки».

Тренд, ещё не стандарт: streaming-вывод текста (Aqua, Handy — но **не** Wispr Flow и Willow),
голосовое редактирование выделенного текста (Aqua Edit Mode, Wispr Flow Command Mode), мышиные
кнопки как триггер.

**Egoist Voice имеет 1, 3, 4, 5 и мышиный триггер. Не имеет 2, 6, 7, 8, 9, 10.**

## 3. Ключевые конкуренты: что брать

### Wispr Flow — лидер по охвату, $15/мес, только облако

Mac + Windows + iPhone + Android, $81M поднято. Проприетарная облачная ASR, **локального режима
нет вообще**. Latency не публикуется («−30 % с начала года»); [конкурентный источник] Willow
оценивает ~700 мс.

Что стоит взять:

- **Двухканальная обратная связь.** Документация: «когда вы слышите ping **или** видите движение
  белых полосок». **Звук назван первым** — он не требует перевода взгляда. У нас звука нет
  вообще.
- **Перетаскиваемость панели к краям с запоминанием.** 9 июля 2026 это чинили с формулировкой:
  панель «could land right on top of something you needed next, like the send button in Gmail».
- **Постепенная деградация присутствия** (Android): авто-сжатие через 5 с бездействия →
  компактная иконка → «крошечная точка»; слайдер прозрачности 20–100 %.
- **Четырёхуровневый Auto Cleanup** (None/Light/Medium/High) с обратимостью — «Undo AI edit»
  возвращает сырой транскрипт.
- **Ранжирование микрофонов** с автопереключением при подключении гарнитуры.

Чего **не** повторять: Flow публично признал серию отказов за июнь 2026 («words swapped for ones
you didn't say», «Rapid growth strained our infrastructure»); Trustpilot 2,7/5; [конкурентные
источники] сообщают ~800 МБ RAM и 8 % CPU в простое на Electron-сборке Windows.

Два пункта из официального Known Issues прямо релевантны нам: **«Missing first words in
transcriptions»** и **«inserts incorrectly on non-QWERTY keyboard layouts»**.

### Aqua Voice — единственные проверяемые цифры на рынке

$8/мес, macOS + Windows + iOS, YC W24. Собственная облачная модель **Avalon**.

- **Latency: старт <50 мс, вставка ~450 мс** — единственные публичные измеримые цифры.
- Avalon 1.5 (апрель 2026): **5,55 % WER**, дебютировала #1 среди проприетарных на независимом
  Open ASR Leaderboard.
- **Два режима вывода**: Instant (нажал → отпустил → текст) и Streaming (слова появляются по мере
  речи и уточняются). Обоснование из документации: *«You wouldn't sweat a Cursor prompt the way
  you would an important email»*.
- **Контекстный чип над пилюлей**: в Edit Mode при удержании клавиши с выделенным текстом
  появляется «12 words selected». Это снимает главную тревогу голосового интерфейса — «а не
  сотрёт ли оно мне текст».
- В январе 2026 отдельно чинили «The microphone UI no longer jumps around when recording» —
  прыгающий UI признан багом уровня релиза.

Слабость: **только облако, офлайна нет ни на одном тарифе**. Русский, по независимому разбору на
Хабре, «работает на стандартном движке».

### Handy — лучший читаемый референс UI-оверлея

MIT, 27,2k★, Tauri 2 + Rust, Win/macOS/Linux. Исходники оверлея прочитаны целиком — это самый
ценный материал всего исследования, потому что коммерческие продукты свои решения не
документируют.

**Геометрия.** Одно нативное окно под все состояния, два форм-фактора:

- **Compact pill**: высота 40 px, `border-radius: 24px`, ширина покоя 172 → рабочая 216; окно
  256 × 46.
- **Live panel** (стриминг): ширина 392 px, `border-radius: 16px`, окно 400 × 120.

Переход между ними — **анимируемый морфинг ширины и радиуса, а не подмена компонента**.

**Раскладка — одна 3-зонная сетка на все состояния**, чтобы центр не прыгал:

```css
grid-template-columns: minmax(22px, 1fr) auto minmax(22px, 1fr)
```

слева — пульсирующая точка 7 × 7 (`sdot-pulse` 1,9 с) **или** спиннер 13 px (0,7 с linear);
центр — waveform **или** метка «Transcribing…»; справа — таймер `mm:ss` с
`font-variant-numeric: tabular-nums` + круглая кнопка отмены 22 × 22 (hover `scale(1.05)`,
active `scale(0.95)`).

**Waveform — 9 полос.** Бэкенд шлёт 16 FFT-бакетов, фронт сглаживает экспоненциально
(`prev*0.7 + target*0.3`) и берёт первые 9. Высота: `max(3, min(18, 3 + pow(v, 0.7) * 15))` —
**гамма-коррекция 0,7 ради живости на тихих сигналах**. Полосы 4 px, радиус 2,
`transition: height 80ms linear`.

**Живой транскрипт**: `committed` + `tentative` текст + мигающая каретка 2 px (`steps(1)`,
1,05 с). Область 64 px со скрытым скроллбаром — вместо него **маска-градиент**
`linear-gradient(to bottom, transparent 0, #000 18px)`: старые строки растворяются под пилюлей.
**Scroll-pin**: авто-follow к низу, отключается если пользователь проскроллил вверх, порог 16 px.

**Анимации**: появление `460 мс cubic-bezier(0.22, 1, 0.36, 1)`, scale 0,92→1 **от прижатого
края**. Уход: opacity 240 мс + scale 300 мс, бэкенд ждёт 300 мс перед `hide()`.

**Позиционирование**: Top / Bottom / None; появляется **на том мониторе, где курсор мыши**.

**Windows-реализация**: `decorations(false).always_on_top(true).skip_taskbar(true)
.transparent(true).focusable(false)` + **принудительный `SetWindowPos(HWND_TOPMOST,
SWP_NOACTIVATE)`, потому что штатный always-on_top перебивается**. Позиция **переустанавливается
ещё раз после `show()`** — `WM_DPICHANGED` затирает первую установку на мульти-DPI.

**Производственный урок**: событие `mic-level` при 24 Гц вызывало неограниченный рост памяти
рендерера. Починили троттлингом до ~30 FPS, **пропуском эмита при выключенном оверлее** и
адресным `emit_to` вместо broadcast.

Handy поддерживает **GigaAM v3 (~225 МБ, русский, с пунктуацией и цифрами) из коробки** — и
находится в feature freeze с приоритетом на 60+ багов.

### Superwhisper — самая формализованная система статуса

$8,49/мес или **lifetime $249,99**, одна лицензия на все платформы. Единственный из платных с
настоящим локальным режимом.

**Три независимых индикатора состояния**, синхронизированных единым цветовым кодом:
**жёлтый = загрузка модели, красный = запись, синий = обработка, зелёный = готово** — в main
window, mini window и меню-баре. Это самая формализованная система статуса в категории.

Официальная разбивка окна записи — 7 элементов, из которых два стоит скопировать:

- **Waveform как диагностический инструмент**: документация прямо пишет «если waveform статичен,
  проверьте устройство ввода и разрешения». Индикатор работает как самодиагностика.
- **Context capture indicator** — «загорается», подтверждая захват контекста.
- **Cancel для записей >30 секунд показывает подтверждение**, <30 с отменяет сразу.

**Mini window** можно оставить всегда активным даже в простое; на hover разворачивает три
контрола.

Windows-версия официально отстаёт: нет FileSync, нет Simulate Keypresses, шаткий автопейст,
нет интерфейса словаря.

### VoiceInk — референс работы с буфером обмена

$25 разово, GPL-3.0, только Apple Silicon. Два стиля панели (`notch` / `mini`), переключаемых в
настройках; при смене стиля панель уничтожается и через 50 мс создаётся заново.

Состояния движка: `.idle`, `.starting`, `.recording`, `.transcribing`, `.enhancing`, `.busy`.
Нажатие хоткея во время `.starting/.transcribing/.enhancing` = **отмена**.

**Лучшее на рынке решение проблемы потерянного буфера** (`CursorPaster.swift`):

- снимок **всех** элементов пастборда со **всеми** типами данных, не только строк;
- **session-ID guard**: перед восстановлением проверяется, что в буфере всё ещё лежит именно наш
  текст **и** служебный тип с UUID сессии. Если пользователь успел скопировать своё —
  восстановление **не выполняется**.

**Power Modes** — автопереключение конфигурации по активному приложению **или URL**: обнаружен
gmail.com → Email Mode с моделью Parakeet V3, промптом «Professional email», включённым
контекстом экрана и auto-send на Cmd+Return.

### Windows: архитектурный разлом, о котором пользователи не знают

**Win+H (Voice Typing)** — **облачный** (Azure), требует интернета. Плавающая перетаскиваемая
панель: круглая кнопка микрофона, шестерёнка, текстовый статус. **Waveform нет.** Автозакрытие
после ~30 с тишины.

**Voice Access** — **локальный, работает офлайн**. Панель пристыкована к верхнему краю, слева —
транскрипция в реальном времени («Refer to this to know what voice access heard» — панель как
инструмент отладки). Wake word «Voice access wake up». Show numbers и рекурсивная числовая сетка.

Что две функции одной ОС имеют противоположную архитектуру приватности — документированный факт.

Новое в 2026: **Fluid Dictation** на Copilot+ PC (локальные SLM расставляют пунктуацию и убирают
«эм», авто-отключается в полях паролей); **Voice Isolation** (июль 2026, отсечение других
говорящих).

Главный дефект Voice Access по отзывам: добавление слов в словарь улучшает **только список
предложений при коррекции, но не первичное распознавание**. Это ровно та ошибка, которую нам
нельзя повторить со своим словарём.

## 4. Чего пользователи просят чаще всего

По убыванию частоты упоминаний в issues, HN, обзорах и заявлениях самих вендоров:

1. **Офлайн / локальная обработка.** Абсолютный лидер. Для Aqua это претензия №1 в рецензии
   9to5Mac. **У нас это уже есть — и это наш главный актив.**
2. **Разовая оплата вместо подписки.**
3. **Стабильность важнее фич.** Одна и та же жалоба на все продукты без исключения, включая
   лидера. У Handy оформлено в feature freeze.
4. **Плавающий индикатор записи с waveform.** Главная жалоба на Whispering. **Есть.**
5. **Не терять первые слова.** У Wispr Flow это официальная статья в Known Issues, у Handy —
   «первые несколько слов обычно теряются». **Решение известно и никем массово не внедрено:
   pre-roll буфер + прогрев модели.**
6. **Голосовая пунктуация и команды форматирования.**
7. **Прозрачная работа с буфером обмена.**
8. **Гибкие хоткеи**: modifier-only, гибрид «короткое нажатие = toggle, длинное = hold».
9. **Code-switching** — вкрапления английского в неанглийскую речь. **Для русскоязычных это боль
   №1**: «Было бы супер иметь модель, заточенную под русский, которая при этом хорошо понимает
   вкрапления английского — ждём». Известная слабость GigaAM: «Gemini → Jemni», «Whisper Large →
   WisperLorge».
10. **Linux.** Полностью отсутствует у всех коммерческих лидеров.

## 5. Как решают вставку текста

Доминирующий подход у **всех**, включая Wispr Flow: буфер обмена + синтетическая комбинация
клавиш, с сохранением и восстановлением прежнего содержимого.

**Критический приём: отправлять виртуальные коды клавиш, а не символы.** Из `clipboard.rs`
Handy с прямым комментарием в коде:

```rust
#[cfg(target_os = "windows")] let (m, v) = (Key::Control, Key::Other(0x56)); // VK_V
// "This ensures the paste works regardless of keyboard layout (e.g., Russian, AZERTY, DVORAK)"
```

Что это не теоретическая проблема, доказывает Known Issue самого Wispr Flow: «inserts incorrectly
on non-QWERTY keyboard layouts». **Мы уже шлём `VK_V` (0x56), а не символ — здесь мы правы.**

**Тайминги — источник половины багов.** Handy: буфер → `sleep(60 мс)`, настраивается 60–200 →
комбинация → `sleep(50 мс)` → восстановить. VoiceInk: `prePasteDelay 0.10 с` → Cmd+V →
восстановление не раньше 0,25 с. Слишком рано нажать Ctrl+V → вставится предыдущее содержимое;
слишком рано восстановить → затрётся то, что не успело вставиться.

**Пять проблем Windows, как их видит рынок:**

1. **UIPI.** `SendInput` инжектит только в приложения равного или меньшего integrity level и
   **при блокировке не сообщает об ошибке** — ни возвращаемое значение, ни `GetLastError`.
   Единственное решение у всех: «запускайте приложение тоже от админа».
2. **Консоли не берут Ctrl+V.** Handy предлагает выбрать Shift+Insert вручную. **OpenWhispr
   автоматически определяет foreground-окно** и для терминалов шлёт Ctrl+Shift+V —
   детектируемый список: Windows Terminal, cmd, PowerShell, mintty, PuTTY, Alacritty, WezTerm,
   kitty, Hyper, MobaXterm, ConEmu. **Это лучшее решение на рынке.**
3. **Раскладка** — см. выше про виртуальные коды.
4. **Гонка буфера** — см. тайминги.
5. **Оверлей поверх всех и без фокуса**: `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)`,
   `focusable(false)`, `skip_taskbar(true)`, с переустановкой позиции **после** `show()`.

**Матрица методов вставки, которую стоит скопировать.** Handy предлагает шесть: Ctrl+V,
Ctrl+Shift+V, Shift+Insert, Direct Input, None (только буфер), External Script. Плюс `Auto
Submit` — Enter через 50 мс после вставки.

**Незакрытые сценарии всего рынка** (кроме одного OSS-проекта на 0★):

- **Что делать, если фокуса нет ни в одном текстовом поле.** Решает только `whisper-local` —
  показывает fallback-окно с уже выделенным текстом и кнопкой копирования. Все остальные молча
  теряют текст либо вставляют не туда.
- **Не вставлять в менеджеры паролей.** Тоже только `whisper-local` (`suppress: true` для
  1Password/Bitwarden). Wispr Flow делает аналог только на Android и только для банков.

### 6.1 GigaAM v3 остаётся правильным ядром

Официальный `evaluation.md` (средний WER по 10 наборам):

| Вариант | Средний WER | Что даёт |
|---|---|---|
| GigaAM v3 RNN-T | **8,3 %** | лучший, но без пунктуации и чисел |
| GigaAM v3 CTC | 9,1 % | быстрее в разы на GPU |
| GigaAM v3 **e2e**-RNN-T | 11,2 % | **пунктуация + нормализация из коробки** |
| GigaAM v3 e2e-CTC | 12,0 % | |
| GigaAM v2 RNN-T | 10,6 % | |
| T-one + LM | 16,3 % | телефония |
| Whisper large-v3 | 21,0 % | |

**Мы платим ~2,9 п.п. WER за e2e-вариант** ради пунктуации и чисел. Это осознанный размен, и он,
скорее всего, правильный: собирать отдельный стек пунктуации и ITN для русского — это две
дополнительные модели в установщике.

Независимый замер на Russian LibriSpeech (`onnx-asr`, воспроизводимая методика): GigaAM v3 RNN-T
— **WER 4,39 %**, e2e-RNN-T — 7,60 %, Whisper large-v3-turbo — 10,10 %, Parakeet TDT 0.6B v3 —
10,95 %.

### 6.2 Три контрнюанса, которые меняют решения

**(а) На шумных записях с реверберацией Whisper выигрывает у GigaAM на 6–19 п.п.** Полевое
исследование с описанной методикой: на чистой студийной речи они идут вровень (7,06 % vs
6,98 %), но GigaAM учился на русском распределении, где сильной реверберации почти нет. Публичный
разрыв «GigaAM сильнее на 5–7 п.п.» на собственных данных не воспроизвёлся.

**Вывод: Whisper нельзя выбрасывать. Его нужно перестать запускать безусловно.**

**(б) Псевдостриминг стоит ≈6 п.п. WER.** Измерено: full-audio 8,07 % → chunked по паузе ≥300 мс
13,86 % → по паузе ≥500 мс 14,47 %. Причина не в потере контекста между чанками (проверено:
разница 0,09 п.п.), а в самих разрывах — модель видит фрагмент без акустической сцены.

**Вывод: streaming делаем опциональным режимом с честным предупреждением, а не дефолтом.**

**(в) VAD-обрезка тишины и AGC — вредительство.** Измерено на шумном корпусе: сырое аудио
26,11 % → VAD-cut **34,04 %** (+7,9) → AGC −20 dBFS **32,24 %** (+6,1) → VAD-cut + AGC
**34,88 %** (+8,8). Аккуратные методы (HPF 80 Гц + pre-emphasis, лёгкий noisereduce, мягкий
компрессор) — wash в пределах 1 п.п.

**Вывод: пункт «обрезка ведущей и хвостовой тишины перед ASR» из первичного плана — вычеркнуть.
VAD использовать только для сегментации и endpointing, не для сплайсинга аудио.**

### 6.3 Hotwords: ограничение, которое нужно обойти

Contextual biasing в sherpa-onnx работает через префиксное дерево ContextGraph, но с двумя
жёсткими ограничениями: **только transducer-модели** и **только
`decoding_method=modified_beam_search`**.

GigaAM в sherpa-onnx присутствует как **NeMo CTC** → **hotwords для нашей текущей модели
недоступны в принципе**, независимо от метода декодирования.

Альтернатива, подтверждённая измерением: детерминированная словарная подмена терминов на
постобработке даёт те же 1–2 п.п., что и нейронная коррекция, **при задержке 0,02 мс вместо
80 мс** и предсказуемом поведении.

### 6.4 LLM-постобработка: доказательства против

Редкий случай прямого воспроизводимого опыта. `ruT5-ASR-large` в наивном виде **ухудшает** WER —
модель «креативит». С пословной фильтрацией через `difflib.SequenceMatcher` (принимать
исправление только при ratio ≥ 0,80–0,85) она удерживала слабый Whisper base от провала
(41 % → 33 %). **На сильной модели эффект отрицательный** — она «исправляет» уже правильный
текст. Из продакшена её выкинули и заменили детерминированной нормализацией чисел + словарной
подменой через `pymorphy3`.

**Вывод: LLM-коррекцию в v2.0 не добавлять.**

### 6.5 Разбивка вклада постобработки (измерено)

| Доработка | Эффект |
|---|---|
| Отключить внутренний VAD Whisper + внешний Silero | **−4 п.п.** |
| Нормализация чисел (пять → 5) | −0,7 п.п. |
| Тематический `initial_prompt` | −0,5 п.п. |
| beam=5 + перебор температур | −0,4 п.п. |
| Подмена IT-терминов (питон → Python) | качество, не WER |
| **Весь стек** | **−10 п.п.** (29,5 % → 19,6 %) |

### 6.6 Что появилось нового и не подходит

- **GigaAM Multilingual** (июль 2026, MIT, 220M и 600M): русский отличный (CV 5,1 % у Large), но
  авторы сами пишут «moderate quality on English» — EN CV 21,5 % против 16–20 % у конкурентов.
  **Для code-switching не подходит.**
- **Nemotron 3.5 ASR streaming 0.6b** (июнь 2026): единственная свежая мультиязычная **потоковая**
  с русским, чанки 80/160/320/560/1120 мс, FLEURS ru 10,84 % @80 мс → 9,17 % @1,12 с. Умеет
  `target_lang=auto` с тегированием языка на уровне высказывания. Официально Linux-only; путь на
  Windows — экспорт в ONNX. **Кандидат для streaming-режима в v2.1, не в v2.0.**
- **Qwen3-ASR** (январь 2026): единая модель offline+streaming, 52 языка, **int8-версия 0.6B уже
  в sherpa-onnx вместе с hotwords**. Отдельных цифр по русскому вендор не публикует.
- **Потоковой версии GigaAM не существует.**

### 6.7 VAD

| VAD | Лицензия | Размер | Latency |
|---|---|---|---|
| Silero VAD v6.2.1 (24.02.2026) | MIT | 2,22 МБ ONNX | <1 мс на чанк |
| TEN VAD | Apache-2.0 | **306–508 КБ** | RTF 0,0086–0,016, −32 % против Silero |
| WebRTC VAD | BSD | единицы КБ | худшая точность |

Оба первых интегрированы в sherpa-onnx. Для push-to-talk достаточно Silero; TEN VAD выигрывает
только там, где нужен быстрый endpointing (hands-free режим).

### 6.8 Производительность: что важно знать

- **Whisper large-v3-turbo на CPU нежизнеспособен для диктовки.** Полевой замер: faster-whisper
  turbo RTF 1,02 на CPU (не успевает за реальным временем) против 0,047 у GigaAM v3 e2e-RNNT —
  **разница >20×**. На GPU они идут вровень.
- **CTC невероятно выигрывает от TensorRT** (RTFx 240 → 1372), **RNN-T — почти нет** (50 → 130),
  потому что RNN-T-декодер авторегрессивный.
- **int8 на CPU для GigaAM v3 почти бесплатна** (RTFx 58,8 → 52,2), а для v2 была катастрофична
  (53,0 → 16,7). Наша текущая INT8-модель — правильный выбор.
- **Вход строго `float32`**: при int16 GigaAM молча возвращает пустую строку без ошибки.
- **Первые 2 вызова ONNX Runtime в 3–5 раз медленнее** — прогрев тихим аудио обязателен. У нас
  его для GigaAM нет.

## 8. Стратегический вывод

Egoist Voice занимает нишу, которая на июль 2026 **фактически пуста**: полностью локальная
диктовка с лучшим доступным русским ASR, с latency ниже, чем у облачных лидеров. Это не
догоняющая позиция, и переработка не должна её размывать.

Отставание сосредоточено ровно в трёх местах, и все три — не про ядро распознавания:

1. **Слой полировки взаимодействия** — тень, морфинг, waveform, звук, тема, доступность.
2. **Слой продуктовых мелочей, которые у всех есть, а у нас нет** — словарь, числа, история,
   восстановление буфера, вставка в терминалы, Esc.
3. **Слой надёжности** — декод на UI-потоке, работа в хуке, DPI, topmost.

Причём третий слой блокирует первый: полировать анимацию, которая замирает на время
распознавания, бессмысленно. Отсюда порядок работ в `03-roadmap.md`.
