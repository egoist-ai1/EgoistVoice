- Date: `2026-08-01T21:01:53Z`

## What changed

- Locked corpus schema v2 to 12 sets / 350 clips with 109 entity expectations,
  quiet phonetics, start/end boundaries, long form and 40/80 translation-command
  positive/negative cases.
- Made script/reference loading strict: manifests, privacy labels, exact counts,
  safe relative IDs/audio, duplicate/unknown-field rejection and script SHA-256.
- Replaced transcript-bearing benchmark output with aggregate-only metrics and
  stable IDs; added model/app/corpus hashes, hardware, exact pipeline parameters
  and resource snapshots.
- Added offline-only model-manager mode, private benchmark log suppression and a
  one-command record/evaluate/freeze runner with atomic output protection.
- Added formal JSON Schemas, corpus documentation and focused privacy,
  determinism, schema, offline and comparison tests.

## Why

Capture thresholds, ASR candidates, entity repair and formatting cannot be
optimized honestly against changing recordings. EV-2201 establishes one
private, hash-locked input and prevents its voice/text/path data from leaking
through reports or internal ASR exceptions before any product behaviour changes.

## How

The existing WPF recorder and hybrid ASR were reused. Default interactive model
behaviour remains unchanged; only corpus benchmark construction passes
`allowModelDownload: false`. Sensitive logging is suppressed on that async flow,
and only numeric scores/stable IDs survive serialization. Immediately before
this checkpoint, `STATUS.md` and `docs/changes/INDEX.md` were re-read; neither
had advanced.
