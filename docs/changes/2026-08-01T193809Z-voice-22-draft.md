## What changed

- Audited current capture, GigaAM/Whisper routing, built-in/user vocabulary,
  command and formatting stages, translation lifecycle, corpus and release
  evidence without changing product behavior.
- Added a Draft 2.2 specification for persistent WASAPI memory capture with
  pre/tail roll, corpus-gated RU/EN ASR and proper-name handling, deterministic
  command/formatting behavior and a protected shared offline Translation Engine
  Host.
- Defined measurable private-corpus, latency/resource, failure, stress,
  installer and clean-machine gates rather than declaring quality from unit
  tests or model-card claims.
- Updated the roadmap/status/spec index while leaving detailed implementation
  tickets blocked until explicit spec approval.

## Why

The current per-press MME recorder has no pre-roll or release tail, so it can
lose boundary phonemes. Current RU/EN handling chooses one complete ASR result
and exact aliases cannot repair every split or malformed named entity. Voice
also depends on a separately running fixed-port translator, which does not meet
the requested always-available offline behavior and cannot safely share model
ownership with EGOIST Translator.

## How

- Source and dated local evidence were treated as the implementation truth;
  fresh official GigaAM, Qwen3-ASR and Hy-MT2 sources informed only benchmark
  candidates, not an unmeasured model replacement.
- The shared engine boundary was aligned with the separate EGOIST Translator
  3.0 Draft: current-user named pipe, typed versioned contract, private
  authenticated llama endpoint, pinned manifests and one owner-safe runtime.
- Immediately before this checkpoint, `STATUS.md` and
  `docs/changes/INDEX.md` were re-read; neither had advanced.
- The required Windows PowerShell 5.1 history-manager invocation exposed an
  existing UTF-8-without-BOM parser failure; no file was changed by the failed
  run. Installed PowerShell 7.6.4 completed the same command successfully.
