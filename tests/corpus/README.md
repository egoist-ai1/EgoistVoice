# Корпус для замера качества распознавания

Без этого корпуса любая правка порогов в селекторе, чанкере или словаре — подгонка под единичные
записи. Полевые данные, на которые опирается `docs/v2/01-market.md`: разница между моделями
держится в пределах ±1 п.п., разница между корпусами — 15–20 п.п., а разница между сырыми и
вычитанными эталонами — 7 п.п. **Один битый эталон сдвигает итоговый WER на 5 п.п. и способен
скрыть 19-п.п. разрыв между моделями.** День на вычитку окупается быстрее недели подбора
архитектуры.

Корпус в репозиторий **не коммитится**: это ваш голос. `.gitignore` исключает `*.wav` и
`reference.jsonl`; здесь остаются только инструкции и схема.

## Структура

```
tests/corpus/
  ru-clean/       20 фраз, тихая комната, обычный темп
  ru-fast/        15 фраз, быстрая речь
  ru-noisy/       15 фраз, фон: клавиатура, вентилятор, музыка
  ru-en-mixed/    25 фраз с английскими терминами  ← главный набор для нас
  ru-numbers/     15 фраз с числами, датами, единицами
  ru-longform/     5 записей 60–180 секунд
  ru-commands/    10 фраз с голосовыми командами
  reference.jsonl эталоны
```

Формат аудио — тот же, что пишет приложение: WAV, 16 кГц, 16 бит, моно.

## `reference.jsonl`

Одна запись на строку. JSON Lines, а не единый массив: файл правится руками при вычитке, и
построчный формат оставляет диффы читаемыми, а слияния — выполнимыми. Строки, начинающиеся с
`//`, пропускаются.

```jsonl
{"id":"ru-clean/001","audio":"ru-clean/001.wav","text":"Проверь пожалуйста последний отчёт и пришли его мне до вечера.","tags":["clean"]}
{"id":"ru-en-mixed/001","audio":"ru-en-mixed/001.wav","text":"Открой pull request в GitHub и запусти Docker Compose.","tags":["mixed","terms"]}
{"id":"ru-numbers/001","audio":"ru-numbers/001.wav","text":"Встреча двадцать пятого июля в пятнадцать тридцать.","tags":["numbers"]}
```

Поле `id` определяет набор по первому сегменту пути — `ru-en-mixed/004` попадает в набор
`ru-en-mixed`. Именно по наборам считается разбивка в отчёте.

## Как записать

1. Закройте Egoist Voice (иначе диагностические режимы не запустятся — они за mutex единственного
   экземпляра).
2. Наговорите фразы обычным для себя способом. Не начитывайте «дикторски»: корпус должен отражать
   вашу реальную речь, иначе он измерит не то.
3. Для `ru-noisy` включите тот фон, в котором вы действительно диктуете.
4. Вычитайте эталоны **вручную**, сверяясь с аудио. Не используйте вывод распознавалки как основу
   — так измеряется согласие модели с собой, а не точность.

## Как прогнать

```powershell
# Приложение должно быть закрыто.
.\bin\Release\net8.0-windows\Egoist.Voice.exe --corpus-benchmark .\tests\corpus .\artifacts\bench\latest.json
```

Отчёт содержит общий WER/CER, разбивку по наборам, p50/p95 воспринимаемой задержки и все гипотезы
целиком — последнее нужно, чтобы разбирать регрессии, а не гадать о них.

Зафиксировать текущий результат как эталон:

```powershell
Copy-Item .\artifacts\bench\latest.json .\artifacts\bench\baseline.json
```

## Гейт

`CorpusGateTests` сравнивает `latest.json` с `baseline.json` и падает, если WER вырос более чем на
0,5 п.п. — общий или по любому набору — либо p95 вырос более чем на 15 %. При отсутствии любого из
файлов тест пропускается: гейт не должен блокировать сборку на машине без корпуса.
